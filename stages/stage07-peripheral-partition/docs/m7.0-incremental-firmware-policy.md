## 交付形式

- 一套版本包含 UP1、UP2 各一份集成 ELF，保持 CPU4/CPU5、原内存与 SGI 分配。
- 各 ELF 累积包含该实例已完成、已分配的驱动与功能；不是将同一 ELF 放到两个核上。
- 先整合已有 CAN（经典/FD/BRS）、RS-232、RS-485、启动日志及诊断，再增量加入 SARADC、ETH2。
- CAN FD2/FD4 仍为用户选择的 SKIPPED/未验证，不能因集成而升级为 PASS。
- 历史单项源码/ELF/原始日志保留为证据与回退点；不再作为默认开发和交付路线。

## 配置与测试

- 波特率、CAN 工作模式与测试选择转为运行时配置，不再按每档参数生成独立交付 ELF。
- 默认启动不自动发送测试帧；测试必须显式启用，且仅面向已确认接线的安全对端。
- 单项、组合及并发测试都运行在同一集成固件内，不再更换固件来测试各接口。
- 每次新增功能，同时回归已有 CAN、RS-232、RS-485、日志/诊断及双实例启停。
- 验证共享 CRU/IOC/GIC 字段、任务/队列与 IRQ 的并发影响，以及单接口停止不影响其他接口。
- 诊断控制通道可以选择测试/配置/读状态，但不能替 UP 代理物理外设字节或收发方向。
- 新增功能仍需自己的单元/驱动验证，不能用某个接口 PASS 代替其他接口的验证。
- 统一固件集成与持久设备树移交是不同工作；未经验证不得宣称冷启动或完整 M7.0 验收。
