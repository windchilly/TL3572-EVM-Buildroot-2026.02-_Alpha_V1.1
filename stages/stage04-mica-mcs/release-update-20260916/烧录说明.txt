二、烧录方式（整镜像，RKDevTool v3.37）
1. RKDevTool 切到"升级固件"页，点"固件"，选择 update-tl3572-openeuler-stage4.img。
2. 板卡进入 Loader 模式（按住升级/RECOVERY 键上电，或 MaskROM）。
3. 点击"升级"，等待所有分区写入完成（rootfs 约 3.7 GiB，耗时数分钟）。
4. 完成后复位，115200 串口（ttyFIQ0 8N1）或 SSH（root 空密码，eth0 DHCP）观察。
注意：整镜像烧录会覆盖 rootfs（含板上 /root 的实验文件与 p3 备份）；
当前板卡已在跑功能等价的手工 v4 内核，是否烧录本镜像请自行决定。

三、烧录后验收（SSH 或串口）
  systemctl --failed                       # 预期 0 个单元
  uname -r                                 # 6.12.69-gf1b67c293213
  cat /proc/cmdline                        # 固化完整串，末尾 maxcpus=7
  nproc; cat /sys/devices/system/cpu/online; cat /sys/devices/system/cpu/offline
                                           # 7 / 0-6 / 7（CPU7 预留）
  ls /lib/modules/                          # 8 个 .ko，含 mcs_km.ko
  insmod /lib/modules/mcs_km.ko && ls -l /dev/mcs && rmmod mcs_km
  grep 134000000 /proc/iomem                # mcs 保留内存
  systemctl start micad && mcsctl status && systemctl stop micad
                                           # active；两实例 Offline 属预期

六、组装与验证记录（可复现，素材见 pack\）
AFPTool v2.28 -pack（pack\ 十件套：8 件厂商原件来自 stage3 已验证素材 +
新 boot.img + 缩容 rootfs.img）得 firmware.img；RKFW 层用 python 手工组装：
厂商头（仅 0x25 处 fw_size 改为 4,118,360,068）+ 厂商 boot 区（逐字节）+
新 firmware + 32 字节整文件 MD5。组装脚本自检：以厂商 firmware 重组厂商
镜像，输出与厂商原文件 SHA256 逐字节一致（c66ffb62...）。

1. RKImageMaker -unpack 回解 success；导出 firmware.img 与原件 SHA 一致
   （99569d34...），导出 boot.bin = MiniLoaderAll.bin = 厂商镜像 boot 区
   （bd3c4eab...）；
2. AFPTool -unpack firmware.img 回解，10 个分区与 pack\ 输入逐字节一致；
3. 头部 python 逐字节 diff：与厂商镜像仅 fw_size 字段 3 字节差异。

验证需经 RKImageMaker 拆外层。
